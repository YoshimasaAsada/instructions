# testscenario.md テンプレート

次の構成を基本とし、該当しない項目は理由つきで `N/A` とする。

```markdown
# テストシナリオ: <機能名>

## 対象差分
- **base:** <develop 等> / **ブランチ:** <ブランチ名>
- **PR / issue:** <番号・タイトル。無ければ N/A>
- **変更ファイル:** <件数と主な内訳>
- **意図:** <PR本文・issue・コミットから読み取った目的を1〜3行>

## 変更の要約
| # | 変更の型 | 対象（ファイル・識別子） | 変更前 | 変更後 |
|---|---|---|---|---|
| C-1 | 既存の振る舞いの変更 | `app/.../foo.rb` の `bar` | 30歳以下 | 32歳以下 |

<実値は変更前後の実コードから取る。「〜など」で打ち切らない>

## 影響範囲
| 影響先 | 経路（なぜ影響するか） | 確認するか | 理由 |
|---|---|---|---|

<空欄を残さない。確認不要にも理由を書く>

## 検証環境・前提
<対象URL（実在するもの）、必要なロール、全シナリオ共通の前提データ。
既存の factory / seed で用意できないものは「要準備」と明記し、test-prep へ引き継ぐ>

## シナリオ一覧

### S-001: <確認の目的が分かる見出し>
- **優先度:** High / **確認手段:** 手動
- **狙う変更:** C-1
- **前提:** <ロール・データの状態>

| # | 操作 | 期待結果（画面で観測できる形） |
|---|---|---|
| 1 | <どの画面のどこから> | <何が見えるか> |

<入力値だけが違うものは、シナリオを分けずにここへバリエーション表を置く>

### S-002: ...

## 自動テストでカバー済み
<手動シナリオから外したもの。変更点 → テストファイルパス + describe / context 名。行番号は書かない>

## 手動では確認不可
<到達手段が無いもの。理由と代替案（自動テスト追加 / ログ確認 / コンソール確認）>

## 手動確認チェックリスト
<手動シナリオを実施順に並べた checkbox。リリース前確認にそのまま使える形>

## 確認事項
<期待結果を決められなかった箇所。論点 / なぜ確認が必要か / 推奨案>

## 対象外・後続対応
```
