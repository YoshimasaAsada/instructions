# decisions.md テンプレート

`{機能名}.decisions.md` の構成。工程が終わるたびに進捗表を更新し、仮確定はその場で追記する（工程の最後にまとめて書かない。中断時に失われるため）。

```markdown
# 決定ログ: <機能名>

> `nonstop` が工程を止めずに進めるために採用した仮確定の一覧。**ユーザー未承認**。
> 覆す場合は `D-n` を指定する。影響範囲は各行の「覆った場合の手戻り」を参照。

## 対象

- **issue:** #<番号> <タイトル> <URL>
- **ブランチ:** <ブランチ名>
- **停止指定:** なし / 設計まで / PRまで

## 進捗

| 工程 | 状態 | 成果物 |
|------|------|--------|
| 要件定義 | 完了 / 進行中 / 未着手 | <path> |
| 技術設計 | | |
| タスク分解 | | |
| テストケース | | |
| 実装 | | |

## 仮確定一覧

- `⚠️` = 「止まる条件」に触れたが保守側を採って続行したもの。最優先で確認する
- `由来` = 各工程文書での ID（`C-1` 等）。無い場合は「-」
- 手戻りコストの大きい順に並べる

| ID | 工程 | 論点 | 採用案 | 根拠 | 由来 | 覆った場合の手戻り |
|----|------|------|--------|------|------|--------------------|
| ⚠️ D-1 | 要件定義 | <論点> | <採用案> | <既定案 / 保守側に倒した理由> | C-1 | <影響するタスクID・ファイル> |
| D-2 | 技術設計 | | | | - | |

## 覆った仮確定

> 下流工程で成立しないと判明し、差し替えたもの。空なら「なし」と書く。

| ID | 何が成立しなかったか | 差し替え後 | 更新した文書 |
|----|---------------------|-----------|-------------|

## 停止した論点

> 「止まる条件」に該当し、保守側の選択肢も無かったためユーザーへ確認したもの。空なら「なし」と書く。

| 論点 | なぜ保守側が無いか | 選択肢 | 状態 |
|------|-------------------|--------|------|
```

## 書き方のルール

- **「覆った場合の手戻り」を空欄にしない。** ここが埋まっていない仮確定は、ユーザーが差し戻し判断をできない。タスクID・ファイルパス・再実行が必要な工程名で書く。
- **根拠は「既定案だから」で終えない。** どの事実（コード・一次情報・既存実装・プロジェクト規約）に基づいて倒したかを1行で書く。
- **論点は事実確認と混ぜない。** 調べれば分かることは調べる。ここに載せるのは意思決定だけ。
