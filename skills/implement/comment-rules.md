# コメント規律の参照リスト

`SKILL.md` の「コメント規律」の参照資料。コメント監査（Phase 4）で1件ずつ判定するときに使う。

## 書かないもの

- **コードの直訳・言い換え。** 処理内容をなぞる説明、セクション見出しコメント（`// バリデーション` 等）。
- **今回の変更セッション固有の経緯メモ。**「〜対応で追加」「レビュー指摘により修正」「以前は〜だった」の類。変更の経緯はコミットメッセージ・PR・`*.task.md` に書き、コードには残さない。
- **仕様書・タスクの識別子（REQ-001 / AC-002 / TASK-003 等）や「設計書 X 章参照」の類**（コメント・テスト名・docstring すべて）。これらの文書は実装完了後に削除される前提のため、コードは文書がなくても読めるように書く。文書との対応は `*.task.md` 側で管理する。
- **コメントアウトした旧コード。**

## 置き場所

説明対象の行の直前に置く。特定の props / 属性 / 引数 / 1行に対する理由コメントは、要素やブロック全体の上ではなく**その行の直前**に付ける（何を説明しているかを位置で示す）。JSX の `{/* */}` は子要素位置専用で、開始タグ内（属性位置）に書くと構文エラーになるため、props 直前のコメントは `//` 行コメントで書く。

```tsx
// 誤り: 要素全体の上に置くと、どの props への注記か読み取れない
{/* キーボード操作でも tooltip を開けるよう tabIndex でフォーカス可能にする */}
<Box as="span" textDecoration="underline" tabIndex={0}>

// 正しい: 対象の props の直前に // 行コメントで置く
<Box
  as="span"
  textDecoration="underline"
  // キーボード操作でも tooltip を開けるよう tabIndex でフォーカス可能にする
  tabIndex={0}
>
```
