# 変更範囲の参照リスト

`SKILL.md` の「変更範囲の原則」の参照資料。差分ごとの判定（このハンクを元に戻したら、受け入れ条件・完了条件・CIのいずれかが破れるか？）で迷ったとき、このリストと突き合わせる。

## 混入しやすい変更（依頼がない限り行わない）

- 既存の関数・クラス・コンポーネントの抽出・統合・リネーム・シグネチャ変更・引数の並べ替え
- 「重複しているから」を理由にした共通化。特に、既存コードを巻き込む共通化は行わない（今回追加するコードとの重複は、既存側を触らずそのまま残す）
- ファイル分割・ディレクトリ移動・import の並べ替えや整理
- 既存コードのスタイル調整（早期リターン化、三項演算子化、`?.` 化、型の厳密化、命名の改善、コメントの書き足し、フォーマット差分）
- 触れる必要のない既存テストの書き換え・整理・移動
- 既存パターンからの離脱（別のライブラリ、別の状態管理、別のエラー処理方式、別のディレクトリ規約の持ち込み）
- 「ついで」の型定義の再編、定数の切り出し、ユーティリティ化
- 変更行の周辺にあるだけの既存バグ・非効率の修正

これらに気づいた場合は、実装せず Phase 5 の改善提案として文書化する。
