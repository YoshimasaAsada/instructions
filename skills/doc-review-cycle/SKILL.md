# Doc Review Cycle

呼び出し元スキルが作成した文書を、渡された観点リストで収束するまでレビュー・修正する共通サイクル。

**呼び出し元から受け取るもの:**

- レビュー対象の文書パス
- 呼び出し元固有の観点リスト
- 採否判定の根拠資料（上流文書・リポジトリ規約・実コードなど）
- 不採用・判定不能の指摘を記録するセクション名（`確認事項` / `未決事項` / `仕様上の確認事項` 等）

## サイクル

1. **文書をレビューする。** 新鮮な目で見るため、対象文書・観点リスト・根拠資料のパスだけを渡したレビュー用サブエージェント（同期実行。非同期起動して待ち合わせない）で行う。サブエージェントが使えない場合は、観点リストを1項目ずつ自分で消化する。呼び出し元の観点に加えて、全文書共通の基底観点を必ず適用する:
   - 記載したファイルパス・識別子・コマンド・URLの実在性
   - 曖昧語の残存（「〜など」による打ち切り、「〜くらい」、検証不能な表現）
   - 上流文書（要件定義書・設計書）との矛盾
2. **各指摘を根拠と突き合わせる。** 指摘を鵜呑みにせず、上流文書・リポジトリの規約（`CLAUDE.md` / `AGENTS.md` / `.claude/rules/` 等）・実コード・ユーザーの方針キーワードと照合し、採用/不採用を理由つきで判定する。一般論として正しくても既存パターンやプロジェクト方針と矛盾する指摘は不採用とする。上流文書の変更を要する指摘・合意済みスコープを広げる指摘は文書へ反映せず、呼び出し元の指定セクションへ推奨案つきで記録する。根拠が見つからず採否を判定できない指摘も、勝手に決めず同セクションへ推奨案つきで残す。
3. **採用した指摘を修正し、呼び出し元の完了条件を再検証する。**
4. **収束条件:** 採用すべき指摘が出なくなるまで繰り返す。上限は3サイクルとし、上限到達時に未解消の採用指摘が残る場合はその内容を報告する。

## 呼び出し元への報告

各サイクルの指摘数・修正した数・不採用とその理由・確認事項へ回した件数を返す。呼び出し元はこれを出力サマリに含める。
