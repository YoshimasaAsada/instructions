# Create Spec

要件テキストを入力に、構造化された仕様書を生成する。

- **目的:** 自然言語の要件を、レビュー・実装に使える仕様書フォーマットに変換する
- **入力:** 要件テキスト（標準入力 or ファイル）
- **出力:** `{name}.spec.md`

---

## 実行フロー

### Phase 1: 要件の読み込みと分析

入力テキストを読み込み、以下を把握する:

- 実現したい機能・目的
- 登場する利用者・システム
- 明示されている制約・条件
- 曖昧な点・解釈が必要な点（後で「前提・解釈」として明示する）

---

### Phase 2: 仕様書の生成

以下の**固定フォーマット**で仕様書を生成する。省略・追加・並び替えは行わない。

```markdown
# 仕様書: {機能名}

## 背景・目的

（この機能を作る理由と、解決する問題を2〜4行で記述）

## 対象ユーザー

（誰が使うかを箇条書きで記述）

## 機能要件

（実現しなければならない機能を番号付きリストで記述。"〜できる" の形式で書く）

1. 〜できる
2. 〜できる

## 非機能要件

（パフォーマンス・セキュリティ・可用性など。該当なければ「特になし」）

## 画面 / API 設計

（UI の場合は画面構成と主要操作フローを記述。APIの場合はエンドポイント・リクエスト・レスポンスの概要を記述）

## 除外スコープ

（今回対応しないことを明記する。誤解防止のために必ず記述する）

- 〜は対応しない

## 受け入れ条件

（この仕様が満たされたと判断できる検証可能な条件を番号付きリストで記述）

1. 〜であること
2. 〜であること

## 前提・解釈

（要件が曖昧だった箇所について、どう解釈したかを記述する）
```

---

### Phase 3: 出力

生成した仕様書を出力する。ファイル名は引数または `feature.spec.md` をデフォルトとする。

出力後に以下を1行で添える:

```
仕様書を生成しました。次のステップ: review-spec.md でレビューを実行してください。
```
